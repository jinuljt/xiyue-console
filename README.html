喜悦 Voice · 控制台

控制台是独立的静态前端，随设备端服务分发，通过同源 HTTP API 管理任务。v0.2 以系统配置、能力配置、状态用量为主；任务应用放在次级入口。音箱尚未连接，支持单独进行文字模型验证。

可用页面

  • 系统总览：设备名称、程序版本、运行时间、已启用能力和各服务配置状态。
  • 系统配置：基本设置、三种运行模式、ASR / LLM / TTS / 外部 Agent，接后端持久保存与校验。
  • 状态与用量：真实进程运行时间、内存和调用记录；无账单时不展示虚构余额。
  • 能力库：配置、启用/停用、导入声明式 JSON。
  • 任务与待办：确认、暂停、继续、取消、查看计时。
  • 定时计划：一次性、每天、工作日执行。
  • 设备与服务：明确显示尚未接入的语音与模型服务。

开发

node --check app.js
# 从 xiyue-agent 启动：
go run . -console ../xiyue-console

无需前端依赖或构建工具。页面须由 Agent 提供，不直接双击 index.html。通过原生 dialog 和表单呈现配置，用户与插件内容均以 textContent 插入。轮询获取状态，倒计时只作为显示，最终执行以 Agent 为准。

房间声音直连

在「能力中心 → 房间声音直连 → 详情」填写局域网 HTTP WAV 地址和播放音量。可在保存前验证音频格式和数据。保存后用「开始听音」或「停止听音」控制音箱。状态区显示连接、重连、让行及最近收到音频的时间。

自动化

「自动化规则」管理一次性、每天和工作日的定时执行。「手动流程」用于导入、查看步骤、配置和运行现有声明式流程。定时规则可调用已启用的流程。现有计划和 JSON 清单兼容原有 Agent API。

边界

不持有定时器业务、不直接调用厂商 API、不在浏览器持久化密钥。密码框只写入服务端凭证存储，保存后清空，只显示配置状态；不会要求普通用户填写凭证条目编号。文字验证通过后仍不代表音箱语音链路已接通。组合模式按显式前缀路由。HTTPS 配对后可以通过控制台管理设备。托管账单与实际音箱语音链路待生产验收。
